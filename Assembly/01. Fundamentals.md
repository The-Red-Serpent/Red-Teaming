## Computer Architecture








## Compiler
When you write a program in C, you are writing instructions in a language that is easier for humans to understand, but the CPU cannot directly understand C. The compiler takes your C code, such as `hello.c`, and translates it into assembly language, producing something like `hello.s`. Assembly is a human-readable representation of the instructions that a particular CPU understands. For example, if you write `x = a + b` in C, the compiler might translate it into assembly such as `add eax, ebx`. The assembler then takes the assembly code in `hello.s` and converts it into actual machine-code bytes that the CPU can execute, producing `hello.o`, which is called an object file. 

This object file may still depend on code from libraries; for example, if your program uses `printf()`, that functionality comes from a library. The linker takes `hello.o` and connects it with the required libraries and other object files, resolving things like where `printf()` comes from, and then produces the final executable, such as `hello`. The operating system can then load this executable into memory and the CPU executes the machine code. 

Different CPUs have different instruction sets, which is why architectures such as x86, x86-64, ARM, etc. have different assembly languages. When reverse-engineering a compiled program, you often don't have the original C code, so tools like Ghidra look at the machine code, disassemble it into assembly, and then try to reconstruct C-like pseudocode. Ghidra cannot recover the exact original C code; it is making an educated guess about what the compiled program is doing.

```
┌──────────────┐
│   hello.c    │  ← You write C
└──────┬───────┘
       ↓
┌──────────────┐
│   Compiler   │  ← Converts C → Assembly
└──────┬───────┘
       ↓
┌──────────────┐
│   hello.s    │  ← Assembly
└──────┬───────┘
       ↓
┌──────────────┐
│   Assembler  │  ← Assembly → Machine code
└──────┬───────┘
       ↓
┌──────────────┐
│   hello.o    │  ← Object file
└──────┬───────┘
       ↓
┌──────────────┐
│    Linker    │  ← Connects code + libraries
└──────┬───────┘
       ↓
┌──────────────┐
│    hello     │  ← Final executable
└──────┬───────┘
       ↓
      CPU
```

## Sections
When writing code in assembly you will be adding sections to the assembly code. These sections are used to organize the code into specific areas of memory. These areas of memory have different purposes during runtime.
| Section Name | Description                                                                | Info                                                                 | Notes                                                       |
| ------------ | -------------------------------------------------------------------------- | -------------------------------------------------------------------- | ----------------------------------------------------------- |
| `.text`      | Contains the code of the program                                           | Executable by the CPU                                                | Read-only to prevent modification                           |
| `.data`      | Houses the static data of the program that will be modified by the program | Usually stores globals and initialized data                          | Most likely will be read-write                              |
| `.bss`       | Stores uninitialized data                                                  | Variables sizes in the section are known but values are 0 at runtime | Saves memory because you don't need to initialize variables |
| `.rdata`     | Stores read only data                                                      | Data is not modified during execution                                | Primary purpose is to hold constant data                    |


sections assemble code into readable, writeable, or readable and writeable segments to help the processor efficiently use memory, obtain higher levels of security, and provide easier management for both the assembler and the operating system. 

## Memory Address
A memory address in assembly is basically a number that tells the CPU where a piece of data is located in RAM, similar to how every house has an address. Memory addresses are usually written in hexadecimal, such as `0x1000` or `0x7fffffffe000`.

## Label
A label in assembly is simply a name you give to a specific location in your code. It lets you refer to that location without having to know the actual memory address. Labels are commonly used with jump instructions, loops, and functions.

### Syntax

```asm
label_name:
    instruction
```

### Example

```asm
mov rax, 0

loop:
    inc rax
    cmp rax, 10
    jl loop
```

Here, `loop:` is a label. When the CPU reaches:

```asm
jl loop
```

it jumps back to the instruction at `loop:`.

So you can think of a label as a **bookmark in your assembly code**:

```text
label:        ← bookmark
   ↓
instruction
instruction
instruction
```

The assembler figures out the actual memory address of the label when it creates the machine code.

## Example
```asm
section .text
global _start

_start:
    mov rax, 5
    jmp add_number

add_number:
    add rax, 10
    jmp done

done:
    ; program ends here

```
