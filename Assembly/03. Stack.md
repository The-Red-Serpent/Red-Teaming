## Stack
The stack is the region of memory that stores local variables, function parameters, and function call information (such as return addresses). Data on the stack only exists while the function is running. When a function returns, all its stack variables are destroyed and the stack pointer moves back. 


To keep track the stack, the system uses the base pointer `rbp` and the stack pointer `rsp`, whereas `rsp` points to the top of the stack and `rbp` points to the bottom of the stack. In the Intel architecture, as program adds data to the stack, the stack grows downward from high memory to low memory. 

When items removed from the stack, stack shrinks upward from low to high memory. When a word value is pushed onto the stack, the memory address of `rsp` decreases 2 bytes and when a word value is popped off the stack, the memory address of `rsp` increases 2 bytes. When a double word value is pushed onto/popped off the stack, the memory address of `rsp` decreases/increases 4 bytes.

## Stack Frame
When a function is called, a stack frame is created to support the function’s execution. The stack frame contains the function’s local variables and the arguments passed to the function by its caller. The frame also contains housekeeping information that allows the called function (the callee) to return to the caller safely. The exact contents and layout of the stack vary by processor architecture and function call convention.

The stack frame can store several kinds of temporary information, especially when functions are called:

- Return addresses : where the CPU should continue after a function finishes.
- Local variables : variables created inside a function.
- Saved registers : register values saved so they can be restored later.
- Function arguments — arguments that are passed on the stack when the calling convention requires it.
- Temporary data — values that need to be stored temporarily during calculations.
- Stack frames — the collection of data associated with a particular function call.
