## Windows Filtering Platform
Windows Filtering Platform (WFP) is a Windows networking framework that provides a set of APIs and filtering mechanisms that allow software to monitor, inspect, and control network traffic. It provides different points in the Windows networking stack where applications or security software, such as an EDR or firewall, can observe network activity and decide whether to allow or block it.

WFP can be used from user mode through its APIs, while more advanced filtering can be implemented using a kernel-mode WFP callout driver.

## Architecture
### Layer

A WFP layer is a predefined point in the Windows networking stack where WFP can inspect network activity and apply filtering decisions. Each layer represents a specific type or stage of network operation, such as an outbound connection or packet processing.

| Layer                                | What it represents                                 |
| ------------------------------------ | -------------------------------------------------- |
| `FWPM_LAYER_ALE_AUTH_CONNECT_V4`     | Application attempts an outbound connection        |
| `FWPM_LAYER_ALE_AUTH_RECV_ACCEPT_V4` | Application receives/accepts an inbound connection |
| `FWPM_LAYER_STREAM_V4`               | TCP stream data                                    |
| `FWPM_LAYER_DATAGRAM_DATA_V4`        | UDP datagram data                                  |
| `FWPM_LAYER_INBOUND_TRANSPORT_V4`    | Incoming TCP/UDP traffic at the transport layer    |
| `FWPM_LAYER_OUTBOUND_TRANSPORT_V4`   | Outgoing TCP/UDP traffic at the transport layer    |
| `FWPM_LAYER_INBOUND_IPPACKET_V4`     | Incoming IP packets                                |
| `FWPM_LAYER_OUTBOUND_IPPACKET_V4`    | Outgoing IP packets                                |


### Filter

A WFP filter is a rule associated with a specific layer that defines **which network activity should be matched and what action should be taken when it matches. A filter can match conditions such as the application, IP address, port, protocol, or user and can allow, block, or invoke a callout.

| Action                           | Meaning                                                                                                                                                                                              |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `FWP_ACTION_PERMIT`              | Allows the network operation to proceed.                                                                                                                                                             |
| `FWP_ACTION_BLOCK`               | Blocks the network operation.                                                                                                                                                                        |
| `FWP_ACTION_CONTINUE`            | Does not make a final decision; WFP continues evaluating other applicable filters.                                                                                                                   |
| `FWP_ACTION_CALLOUT_TERMINATING` | Invokes a callout that can make a final filtering decision, such as permit or block.                                                                                                                 |
| `FWP_ACTION_CALLOUT_INSPECTION`  | Invokes a callout for inspection while allowing classification to continue; typically used when the callout needs to inspect or collect information rather than immediately terminate the operation. |
| `FWP_ACTION_CALLOUT_UNKNOWN`     | Indicates a callout action whose behavior is not known to the filtering engine; generally used for callouts that don't fit the terminating or inspection categories.                                 |


### Callout

A WFP callout is a mechanism that allows a kernel-mode driver to provide custom inspection or processing logic for network activity. When a filter references a callout and the filter is selected during classification, WFP invokes the callout's functions in the registered driver, allowing software such as an EDR to inspect the activity and potentially permit, block, or defer the operation. hey allow third-party drivers (such as EDR products) to implement custom inspection logic that goes beyond the built-in permit/block actions.


## Call Out Driver
A WFP callout driver is a third-party or custom kernel-mode driver that integrates with Windows Filtering Platform (WFP). WFP itself is the Microsoft-provided framework that manages network filtering, while the callout driver provides custom inspection logic. The driver registers a callout with WFP and tells WFP which type of network traffic it is interested in and at which filtering layer it should be invoked. When matching traffic reaches that point, WFP calls the driver’s callback function, allowing the driver to inspect the traffic and recommend an action such as permit, block, drop, or continue.

When an EDR product wants to intercept and process network traffic on a host, it most likely uses a WFP callout driver. From an EDR perspective, a WFP callout driver is a kernel-mode driver that an EDR uses to monitor and potentially control network traffic on an endpoint. The EDR's callout driver registers a callout with WFP at the filtering layer where the EDR wants visibility. When network traffic reaches that layer and matches the EDR's filtering conditions, WFP invokes the callout driver's callback, allowing the EDR to inspect the traffic and apply its detection logic.
