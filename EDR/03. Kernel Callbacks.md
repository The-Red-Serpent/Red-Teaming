## Kernel Notification Callback
The kernel's callback mechanism provides a general way for drivers to request and provide notification when certain conditions are satisfied.

A driver can create a callback object, and other drivers can request notification for conditions associated with this driver-defined callback. In addition, the system defines three callback objects for driver use.

A Windows kernel notification callback is a mechanism provided by the Windows kernel through specific kernel APIs/DDIs that allows a kernel-mode driver to register its own callback function for a particular type of system event. Windows exposes different registration APIs for different event types, such as process creation, thread creation, DLL/EXE image loading, registry operations, and certain process/thread object operations. Once a driver registers its callback, the Windows kernel maintains that registration and invokes the driver's callback when the corresponding event occurs, passing event-related information to the driver.

EDRs use Windows kernel notification callbacks as a telemetry mechanism, the EDR’s kernel-mode driver registers callback functions through Windows-provided kernel API When a relevant event occurs, Windows invokes the registered callback and passes event-related data to the EDR driver, such as information about the event, process, thread, image, or operation, depending on the callback mechanism. The EDR driver can then collect and send this telemetry to the EDR’s user-mode components or other security-processing components, where it is correlated and analyzed with other telemetry to determine whether the activity is suspicious or malicious and, depending on the product, may generate an alert or take a protective action.

## Types
### Pre-operation callback

A pre-operation callback is a kernel callback routine that Windows invokes before a monitored operation is completed, allowing a registered driver to inspect the operation and, where the specific callback mechanism permits, modify or prevent the operation before it proceeds.

### Post-operation callback

A post-operation callback is a kernel callback routine that Windows invokes after a monitored operation has been processed, allowing a registered driver to inspect the outcome and collect information about the operation and its result.

## Process-Creation Kernel Callbacks

Process-creation callbacks notify a registered driver when a process is created or terminated. Windows passes information about the process to the EDR, such as its process ID, parent process, executable path, and command line. The EDR can use this information to build process activity records and detect suspicious process behavior.

## Thread-Creation Kernel Callbacks

Thread-creation callbacks are Windows kernel callbacks that allow a driver, such as an EDR, to be notified when a thread is created or terminated. When the event occurs, Windows calls the registered callback and provides basic information about the thread, including the process ID, thread ID, and whether the thread is being created or terminated.

## Object Kernel Callbacks

Object notifications are a Windows kernel callback mechanism that allows a driver, such as an EDR, to be notified when certain process, thread, or desktop handle operations occur. EDRs use these notifications because suspicious activity often involves obtaining or duplicating handles to processes or threads.


## Image Kernel Callbacks

Image-load notifications are Windows kernel callbacks that allow a driver, such as an EDR, to be notified whenever an executable, DLL, or kernel driver is loaded into memory. Windows calls the registered callback and provides information about the image, allowing the EDR to collect telemetry and analyze what code is being loaded into a process.

The callback can receive information such as:

* Image name/path
* Process ID where the image was loaded
* Base address
* Image size
* Whether it is a user-mode or kernel-mode image
* Code-signing information
