## File system filter driver
A file system filter driver in Windows is a specialized kernel-mode software component that intercepts, monitors, logs, modifies, or blocks input/output (I/O) requests before they reach the main file system

When a user-mode application requests to interact with a file (e.g., opening, reading, or writing), the request transitions into kernel mode, where the I/O Manager processes it and generates an I/O Request Packet (IRP). This IRP is then passed through a stack of drivers before reaching the file system driver. As shown in the diagram, the flow follows:

- User Mode Request — A user-mode application makes a request to interact with a file
- I/O Manager — The request enters kernel mode, where the I/O Manager processes it and creates an IRP.
- Legacy Filter Driver A — This driver intercepts the request and can inspect, modify, or block it before passing it further down the stack.
- Legacy Filter Driver B — Another filter driver that has the opportunity to process the IRP before forwarding it.
- Filesystem Driver (e.g., ntfs.sys) – The final destination of the IRP, where the file system driver handles the operation and interacts with the storage device.

![image](https://www.easefilter.com/images/FilterDriver.png)


Legacy filter drivers were harder to manage because developers had to deal directly with the driver stack and IRPs. This could cause complexity, conflicts, crashes, and performance issues.

Microsoft introduced Filter Manager (fltmgr.sys) to solve this.

Minifilters use Filter Manager, which handles the complicated driver-stack management and ordering for them.



## Minifilter
A Minifilter operates on top of the Windows Filter Manager (fltmgr.sys). The Filter Manager receives file I/O requests from the I/O Manager and forwards them to the registered Minifilter drivers in the order determined by their altitude. In other words, the altitude controls the order in which filters are loaded and invoked.


![image](https://hackyboiz.github.io/2025/08/15/banda/Minifilter-Driver/en/image2.gif)



An EDR registers a kernel-mode filesystem minifilter with Windows' Filter Manager. The minifilter registers callbacks for specific filesystem operations, such as file creation, writing, or deletion. When those operations occur, the I/O system routes the request through Filter Manager, which invokes the EDR's registered callbacks, allowing the EDR to collect telemetry and potentially take action.
