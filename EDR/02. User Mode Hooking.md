## User Mode Hooking
User-mode hooking is a technique where an AV/EDR modifies functions loaded in a process’s user-mode memory to redirect execution to its own code, allowing it to inspect, monitor, or block operations before the original function executes.

## System Call
A **system call (syscall)** is the mechanism Windows uses to allow a user-mode application to request services from the kernel. Applications normally interact with Windows through APIs such as `OpenProcess()`, but operations involving privileged resources, such as processes, memory, and kernel objects, ultimately require kernel-mode code. On 64-bit Windows, functions in `ntdll.dll`, such as `NtOpenProcess()`, act as the user-mode interface to these kernel services.

These functions prepare the required arguments and execute the `syscall` instruction, which transfers execution from user mode to kernel mode. The Windows kernel then performs the requested operation and returns the result to the application. By intercepting calls to these APIs, an EDR can observe the parameters passed to the original function, as well as the value returned to the code that called the API. Agents can then examine this data to determine whether the activity was malicious
