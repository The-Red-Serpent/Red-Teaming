Windows separates memory and execution into two distinct privilege levels: user mode and kernel mode.

- User Mode: This is where all your applications run (e.g., your browser, text editor, and your shellcode loader). Processes in user mode are isolated from each other and have restricted access to system hardware and critical OS data.
- Kernel Mode: This is the privileged core of the operating system. The kernel and its drivers run here, with complete access to all system resources.

When a user-mode application needs to perform a privileged action like allocating memory in another process, writing to a file, or opening a network socket it cannot do so directly. 
It must ask the kernel for help by making a system call (or syscall).

The bridge between user-mode applications and the kernel's syscall functionality is a critical DLL: ntdll.dll. High-level functions you might use, like WriteProcessMemory from kernel32.dll, eventually call a corresponding function inside ntdll.dll (e.g., NtWriteVirtualMemory). 
This ntdll.dll function is the last stop in user mode before the execution context switches to the kernel to fulfill the request.

This makes ntdll.dll the perfect chokepoint for an EDR to monitor what a process is trying to do.
