## Event Tracing for Windows
Event Tracing for Windows is a powerful, built-in logging and tracing framework in the Windows operating system. ETW enables efficient collection, logging, and analysis of detailed events from both user-mode applications (like software running in user space) and kernel-mode components (such as device drivers or core OS functions). ETW provides deep insights into what is happening across the operating system. It captures detailed system activities, including system calls, process lifecycles, registry/file changes, and network operations, offering deeper insights than traditional Windows Event Logs.

One of the primary advantages of leveraging ETW within EDR/XDR solutions is its ability to capture a wide array of system events with minimal performance impact. ETW allows for the monitoring of various aspects of system behavior, including process creation, network activity, registry modifications, and more. This comprehensive visibility empowers EDR/XDR platforms to detect and investigate suspicious activities in real-time.

## Event Log
The Event Log is a structured, persistent logging database (the .evtx files you browse in Event Viewer). ETW is the underlying publish-subscribe messaging bus that feeds many different consumers - the Event Log being just one of them. Most high-frequency security-relevant events, like process injection primitives or .NET assembly loading, never make it into the Event Log at all. They live exclusively in ETW trace sessions.

## ETW Workflow

### Controller starts the trace session
- The controller creates and starts an ETW trace session.
### Trace session allocates buffers
- The session maintains in-memory buffers where event data is temporarily stored.

### Controller enables providers
- The controller enables one or more ETW providers for the session. This tells the providers which events to generate and send to the session.

### Providers generate events
- When something happens that a provider is instrumented to report, it generates an ETW event.

### Events are written to the session's buffers
- The events are delivered to the trace session and placed into its buffers. The buffers therefore act as the storage/transport area between providers and consumers.
### Consumer reads the events
- A consumer connects to the session and reads events from the buffers, either in real time or from a trace log after the session is stopped.

## ETW Components 

### Providers
Providers are components that generate events and send them to ETW sessions. It can be a user mode application, a system component, or a kernel mode driver. Providers log information about specific activities such as process creation, file or registry changes, or network operations. Each provider is identified by a unique GUID and can be enabled or disabled by a controller for a specific session. Providers define the types of events they can emit and include metadata such as event IDs, levels, and keywords. If a third‑party application wants to generate ETW events, it must first register as an ETW provider.

Windows ships with over 1,000 registered ETW providers by default, covering everything from process creation and network I/O to .NET CLR runtime events and kernel memory operations. EDRs like Microsoft Defender ATP, CrowdStrike Falcon, and SentinelOne all consume specific ETW providers - particularly the privileged ETW Threat Intelligence (ETWTI) provider - as core detection telemetry sources.

### ETW Provider Types
- MOF Provider: An ETW provider that uses Managed Object Format (MOF) definitions to describe the structure and metadata of its events. MOF-based providers were widely used by older Windows components and system instrumentation.
- WPP Provider: An ETW tracing provider that uses the Windows Software Trace Preprocessor (WPP) and tracing macros in source code to generate diagnostic and debugging events. WPP is commonly used in Windows drivers and low-level system components.
- Manifest-based Provider: An ETW provider whose event definitions and metadata are described in an XML manifest. The manifest specifies information such as event IDs, levels, keywords, channels, and payload fields, allowing consumers to interpret the events.
- TraceLogging Provider: An ETW provider that uses the TraceLogging API to generate events while specifying much of the event metadata directly in the tracing code. It simplifies ETW instrumentation by reducing the need for a separate event manifest.

<br></br>

- Enumerate Providers
```
logman query providers
```
- Enumerate Specific Providers
```
logman query providers "<ProviderNameOrGUID>"
```




### Controllers
A controller is an application that manages ETW sessions. It creates, starts, and stops sessions. It chooses where logs are saved and how the log file is handled. It enables or disables providers so they can send events to a session. It sets the size and number of buffers, which are temporary storage for events. It reports session statistics such as buffers used, buffers delivered to consumers, and events or buffers lost. These controls keep event collection efficient for live viewing or later analysis.

### Logman Controller Modes 
- Ad-hoc ETW Session (-ets): An ETW trace session that is created and started immediately by logman. It is intended for temporary, on-demand tracing. When the session is stopped, the active ETW session is removed.
- Persisted Data Collector Set (DCS):
A saved tracing configuration that defines how an ETW session should be collected. Creating the DCS does not start tracing; the configuration must be explicitly started and stopped. Because the configuration is persisted, it can be reused for future tracing sessions.

<br></br>

- Create and start a trace session with an <sessionname> as an ETW session and enable the provider with a defined <provider>
```
logman create trace MySession -p "Microsoft-Windows-Kernel-Process" 0x10 5 -o C:\Logs\MySession.etl -ets
```
- p: Specifies the provider (in quotes due to hyphens) with keywords (0x10 for process events) and level (5 for informational).

- o: Sets the output .etl file path.

- ets: Creates and starts an active ETW session visible in logman query -ets.



### Trace Session:
A session is a container that collects events from one or more providers. It uses buffers to hold incoming events, applies filters based on level or keywords to decide what to keep, and then either streams events in real time to consumers for live analysis, writes them to an etl Event Trace Log file for later review, or does both. So, you can think of a trace session as a container that collects events from one or more providers. A single trace session can have multiple providers enabled at the same time.

 - List all active trace sessions.
```
logman query -ets
```
- List a specifc Session
```
logman query MySession -ets
```


### Consumers
A consumer is a tool or application that reads and analyzes events collected by an ETW session. It can process events in real time or from saved .etl files to display, filter, or interpret data. Some ETW providers also write to Windows Event Log channels, which can be viewed using Event Viewer. However, Event Viewer does not read directly from ETW sessions. Consumers are also known as subscribers.

### Channel
A channel is a named destination used by the Windows Event Log system to organize and store events. When a provider publishes an event to a channel, the Windows Event Log service handles that event and stores it in an event log file (.evtx). You can then view those events through the Windows Event Viewer GUI. Channels are organized pipelines that collect events and save them to .evtx files, usually in C:\Windows\System32\winevt\Logs.

Additionally, The events can also be accessed via applications that interface with the Windows Event Log service, including log aggregators such as Splunk and Wazuh, as well as custom software built on Windows APIs.

- List all channels:
```
Get-WinEvent -ListLog * | Select-Object LogName, IsEnabled, MaximumSizeInBytes
```
- Show details for the PowerShell Operational channel:
```
Get-WinEvent -ListLog "Microsoft-Windows-PowerShell/Operational" | Format-List *
```
- Read recent events from a channel:
```
Get-WinEvent -LogName "Microsoft-Windows-PowerShell/Operational" -MaxEvents 50
```

## EDR Telemetry
| Provider                                         | Telemetry produced                                                                                                                                                 |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `Microsoft-Windows-Threat-Intelligence` (ETW-TI) | Kernel-emitted security events: process creation, image mapping, memory-protection changes, RWX commits, `SetThreadContext`. Consumer must run as PPL-Antimalware. |
| `Microsoft-Windows-Kernel-Process`               | Process and thread lifecycle events; image load and unload                                                                                                         |
| `Microsoft-Windows-Kernel-File`                  | File create, read, write, and delete operations                                                                                                                    |
| `Microsoft-Windows-Kernel-Network`               | TCP/UDP connection state changes                                                                                                                                   |
| `Microsoft-Windows-Kernel-Memory`                | Memory allocation and protection-change events                                                                                                                     |
| `DotNETRuntime`                                  | `Assembly.Load`, JIT compilation, and AppDomain creation                                                                                                           |
| `Microsoft-Antimalware-AMSI`                     | AMSI scan request and result events for scripts and .NET assemblies                                                                                                |
| `Microsoft-Windows-PowerShell`                   | Event ID 4104 script-block logging, including decoded script content                                                                                               |
