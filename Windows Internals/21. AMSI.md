## AMSI
Antimalware Scan Interface is a Windows security interface/API that allows applications and services to submit potentially malicious content to an installed antimalware product for inspection. It is vendor-neutral: AMSI itself does not decide whether something is malware; an AMSI provider (such as Microsoft Defender or another security product) performs the actual analysis. AMSI is Microsoft’s mechanism for scanning content at runtime, before script engines execute it. It’s loaded as a DLL (amsi.dll) into every scriptable host. AMSI enables dynamic content scanning, especially for interpreted languages such as:

- PowerShell
- VBScript
- JScript
- WMI and more

AMSI is vendor-independent and provides open Win32 API and COM interfaces for the developer to use. Since Microsoft manages AMSI itself, the latest malware signatures are auto-updated in it. Hence, a developer can integrate AMSI quite easily to protect its consumers from dynamic, script-based malwares. AMSI works on signature-based detection. This means that for every particular malicious keyword, URL, function or procedure, AMSI has a related signature in its database. So,  if an attacker uses that same keyword in his code again, AMSI blocks the execution then and there

## Workflow:
When supported processes (e.g., PowerShell, JScript, VBA) load, Windows injects the amsi.dll library. This DLL exposes functions such as "AmsiInitialize", "AmsiScanBuffer", and "AmsiScanString", which allow those processes to forward in-memory buffers of commands, scripts, or other code for scanning. The antimalware provider then evaluates the submitted content and returns whether it is clean, malicious, or suspicious.

- A script engine (like PowerShell.exe or wscript.exe) wants to execute dynamic content.
- Before executing it, the engine calls AmsiScanBuffer() to send the content to AMSI.
- AMSI communicates with the registered antivirus provider (e.g., Windows Defender) via COM.
- The antivirus scans the content in memory.
- If malicious, the antivirus can block execution (e.g., by setting a return code indicating malware).
- If clean, the script proceeds as normal.

## Core functions used of AMSI

- AmsiInitializeInitializes AMSI for an application and returns a context handle.
- AmsiOpenSessionOpens a session between your app and AMSI (optional, for advanced scanning).
- AmsiContextHandle used to point the environment context.
- AmsiScanBufferThe core scanning function. Sends data to be scanned by the AV engine.
- AmsiScanStringSimplified version for string scanning.
- AmsiResultIsMalwareChecks whether the scan result indicates malware.
- AmsiCloseSessionCloses the session.
- AmsiUninitializeFrees the context.
