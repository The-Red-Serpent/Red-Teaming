## Active Directory Certificate Services
Active Directory Certificate Services (AD CS) is a Microsoft Windows Server role that provides Public Key Infrastructure (PKI) services. It allows an organization to issue, manage, renew, and revoke digital certificates for users, computers, servers, applications, and other network devices.

## Components of ADCS

### 1. Certificate Authority
A Certificate Authority is a trusted entity within a PKI that validates certificate requests and issues, renews, and revokes digital certificates.

There are two main types:

- Root CA: The top of the trust hierarchy. Typically kept offline for security.
- Subordinate (Intermediate) CA: Issues certificates to end entities and is trusted because it chains up to the Root CA.

CAs can also be:

- Enterprise CAs: Integrated with Active Directory, allowing for automated certificate issuance based on AD accounts and policies.
- Standalone CAs: Not integrated with AD; require manual approval and are used for external entities or in simple setups.

### 2. Certificate Database
The Certificate Database is the storage maintained by the CA that contains information about certificate requests, issued certificates, and revoked certificates.

### 3. Certificate Revocation List (CRL)

A CRL is a digitally signed list published by a CA that identifies certificates that have been revoked before their expiration date.

### 4. Certificate Template
A Certificate Template is a predefined set of rules and settings that determines how a certificate is issued, who can request it, its validity period, and what purposes it can be used for.

### 5. Certificate Authority Web Enrollment
CA Web Enrollment is an optional AD CS role service that provides a web-based interface for users and administrators to submit certificate requests and retrieve certificates.

### 6. Online Responder
An Online Responder is an AD CS role service that provides real-time certificate revocation status using the Online Certificate Status Protocol (OCSP).

### 7. Network Device Enrollment Service (NDES)
NDES is an AD CS role service that enables network devices and other devices that cannot directly use standard certificate enrollment methods to obtain certificates, typically through SCEP.

### 8. Digital Certificate : An electronic document housing identity details, such as user
or organizational names, and a corresponding public key. These certificates serve for
authentication, proving a person's or device's identity.

### 9. Certificate Enrollment
Certificate Enrollment is the process by which a user, computer, or device requests, receives, and installs a digital certificate from a Certificate Authority.


## Enrollment Process
To obtain a certificate from ADCS, clients need to go through the process of enrollment.
### 1. Find an Enterprise CA :
The first step for clients is to find an Enterprise CA, which is based on the objects in the Enrollment Services container.
### 2. Generate a public-private key pair and create a CSR : 
Clients generate a public-private key pair and create a certificate signing request (CSR) message. This message contains the public key along with various other details such as the certificate template name and subject of the certificate.
### 3. Sign the CSR with private key and send to Enterprise CA server : 
Clients sign the CSR with their private key and send it to the Enterprise CA server.
### 4. CA check if the client is authorized to request certificates : 
The CA server checks if the client is authorized to request certificates. If so, it looks up the certificate template AD object specified in the CSR to determine whether or not to issue a certificate. The CA checks if the certificate template AD object's permissions allow the authenticating account to obtain a certificate.
### 5.  CA generate the certificate, sign it and if allowed, send it to the client : 
If the permissions allow, the CA generates a certificate using the "blueprint" settings defined by the certificate template, such as EKUs, cryptography settings, and issuance requirements. If allowed by the certificate's template settings, the CA uses other information supplied in the CSR and signs the certificate using its private key and returns it to the client.
