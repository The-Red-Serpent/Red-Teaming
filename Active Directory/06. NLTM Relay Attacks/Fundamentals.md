## Message Signing
NTLM message signing is a mechanism that  provides message integrity and helps mitigate certain NTLM relay attacks by allowing the client and server to verify that messages have not been modified after authentication. It does not encrypt the message itself that is the job of NTLM sealing.

When NTLM message signing is enabled, the client and server first agree to use signing during the NTLM authentication process. After successful authentication, both sides independently derive the same session key using the client challenge, the server challenge, and information derived from the user's password hash. Importantly, the password hash is never sent across the network; each side computes the session key locally. Once the session key is established, all messages between the client and server are signed using a MAC. The MAC is generated by applying a cryptographic algorithm to the message and the session key. The server can verify the MAC by using the same algorithm as the message and the session key and comparing the result to the MAC provided by the client. If the server's computed MAC matches the one received from the client, it knows the message has not been altered and was sent by someone who possesses the correct session key. If an attacker intercepts and modifies the message, the original MAC will no longer match the modified message. Since the attacker does not know the user's password-derived secret and therefore cannot derive the session key, they cannot generate a valid MAC, causing the server to detect the tampering and reject the message.
